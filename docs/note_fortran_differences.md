## 1 通気層の換気量の式

**Fortran 版**（1008〜1033 行、140〜165 行）

```fortran
      GMAQ1=353.25/(TEMP_CAVITY(K))
      GMAO=353.25/(TMPO)
      PQ1=GMAO-GMAQ1
      D1=0.5*ABS(PQ1)*HIGHT_CAVITY(K)*9.8                !中性帯　高さ中央 0.5, 重力加速度 g(ρ-ρ)
...
      IF(L5.EQ.2.AND.ALPK(IW,K).GT.0)QQ(LW,K)=DSQRT(D1)*4.*ALP_TOTAL(K)
```

- 式にすると、 $Q = 4 \thinspace \alpha A_{\mathrm{total}} \sqrt{0.5 \thinspace g H |\rho_o - \rho_i|}$（m³/s）です。
- $\alpha A_{\mathrm{total}}$ は、各階の相当開口面積を直列に合成した値（ $1 / \sqrt{\sum 1 / (\alpha A)^2}$、コメント「相当開口面積αAの直列合成」）、 $H$ は各階の高さの合計（コメント「通気層高さの合計」）、通気層の温度は各階の通気層の温度を高さで重み付けした平均です。
- 0.5 は、コメント「中性帯　高さ中央 0.5」から、中性帯を高さの中央とし、入口と出口のそれぞれに、高さの半分の浮力の圧力差がかかるとしたものと読みました。

**Python 版**（`modules/wall_geometry.py` の `AirNode.ventilation_rate`）

$$
q_v = \frac{\alpha \thinspace d}{L_{\mathrm{vert}}} \sqrt{\frac{2 g H |\rho_o - \rho_i|}{\rho_o}}
$$

- オリフィスの式 $V = \alpha A \sqrt{2 \Delta P / \rho}$ に、浮力の圧力差 $\Delta P = g H |\rho_o - \rho_i|$ を入れ、壁の面積で割って壁 1 m² あたりにしています（ $A$ は通気層の厚さ × 壁の横の長さ）。
- 壁は 1 枚（1 階分）だけを扱い、入ってくる空気は外気としています。
- 空気の密度は $353 / T$ です。

**違い**

- Fortran 版の式には、平方根の中を空気の密度で割る所がありません。
- Python 版は、入口・出口・通気層の中の損失を 1 つの流量係数にまとめ、高さ全体の浮力の圧力差を使います。Fortran 版は、中性帯を高さの中央として、高さの半分の圧力差を使います。
- 係数 4 の意味がわかりませんでした。 $4 \sqrt{0.5} = \sqrt{8}$ なので、同じ相当開口面積で比べると、Fortran 版の換気量は Python 版の $2 \sqrt{\rho_o}$ 倍、外気 0〜30 deg.C で約 2.2〜2.3 倍になります。
- 空気の密度の係数が、353.25 と 353 で違います。

**確認したいこと**

1. 係数 4 は、何を表していますか。0.5（中性帯を高さの中央とする）の読み方も、合っているか教えてください。
2. 平方根の中を空気の密度で割らないのは、意図したものですか。オリフィスの式では、流速は $\sqrt{2 \Delta P / \rho}$ になると考えています。
3. 空気の密度の係数 353.25 は、どこから来た値ですか。

## 2 換気で入る熱の容積比熱 1300

**Fortran 版**（866〜876 行）

```fortran
   D1=1300.*DX(IW,K)*AW(LW)/DTM
...
     UHEN=D1*HTMP(LW,I)+D4+D5+1300.*QQ(LW,K)*TMPO
...
   SAHEN=D1+D2+1300.*QQ(LW,K)
```

通気層の空気の熱容量と、換気で入る熱の両方に、空気の容積比熱として一定の 1300 J/(m³ K) を使っています。

**Python 版**（`modules/balance.py` の `heat_capacity_is`・`heat_residual_is`）

空気の比熱 1005 J/(kg K) と、温度から求めた空気の密度 $353 / T$ の積を使っています。熱容量は通気層の空気の温度、換気で入る熱は外気の温度で求めます。容積比熱は、0 deg.C で約 1300、20 deg.C で約 1210、35 deg.C で約 1150 J/(m³ K) です。

**確認したいこと**

1. 1300 J/(m³ K) は、0 deg.C 付近の空気の値と考えてよいですか。温度で変えなかったのは、計算を簡単にするためですか。

## 3 通気層の空気の質点の水分のたくわえと潜熱

**Fortran 版**（1205〜1236 行の水分の式、866〜868 行の熱の式）

```fortran
   D1=ALD(LW,K,1)+ALD(LW,K,2)+DGDUQ(LW,K)*QQ(LW,K)
```

```fortran
   D2=ALF(LW,K,1)+ALF(LW,K,2)+RW*(ALDT(LW,K,1)+ALDT(LW,K,2))
   D4=(ALF(LW,K,1)+RW*ALDT(LW,K,1))*TMP(LW,I-1)+(ALF(LW,K,2)+RW*ALDT(LW,K,2))*TMP(LW,I+1)
   D5=RW*(ALD(LW,K,1)*(WPU(LW,I-1)-WPU(LW,I))+ALD(LW,K,2)*(WPU(LW,I+1)-WPU(LW,I)))
```

- 水分の式には、時間刻みで割った項（たくわえ）がありません。通気層の空気の質点の水分量を 0 として、各時刻で定常の式を解いていることになります。
- 熱の式には、通気層の空気の質点に入る水蒸気の流れに蒸発潜熱 RW を掛けた項（D5 と、D2・D4 の RW の項）があります。

**Python 版**（`modules/wall_geometry.py` の `AirNode.water_amount`、`modules/balance.py` の `heat_residual_is`）

- 通気層の空気の質点の水分量は、水蒸気の密度 × 通気層の厚さとしています。たまる水分と、換気で入る水分を同じ量（水蒸気の密度）で書くので、水分が厳密に保存されます。
- 通気層の空気の質点では、凝縮熱を数えません。通気層の空気では、水分はすべて水蒸気のままで、相変化は起きないと考えるためです。材料と同じように水蒸気の流れの差に潜熱を掛けると、換気で入った水蒸気がつながりから出ていくとき、通気層で蒸発したと見積もってしまいます。

**確認したいこと**

1. 通気層の空気の質点の水分のたくわえを 0 としたのは、空気の水分の量が材料に比べて小さいからですか。
2. 通気層の空気の質点の熱の式に、水蒸気の流れの潜熱を入れているのは、どのような考えによるものですか。通気層の中で結露・蒸発が起きる（たとえば、通気層に面する材料の表面の結露の熱を、空気の質点で数える）ことを考えたものでしょうか。

## 4 水蒸気の流れの求め方（偏微分に分けるか）

**Fortran 版**（694〜724 行、SUBROUTINE CALDGDU）

水蒸気の流れを、水分化学ポテンシャルの差の項（ALD、 $\partial x / \partial \mu$ を使う）と、温度の差の項（ALDT、 $\partial x / \partial T$ を使う）に分けて書いています。換気で入る水分も、同じように DGDUQ・DGDTQ を使って分けています（1212〜1221 行）。

**Python 版**（`modules/balance.py` の `vapour_flow_ks`、`moisture_residual_is`）

水蒸気の流れは、両側の水蒸気圧の差を透湿抵抗で割って求めます。換気で入る水分も、外気と通気層の空気の水蒸気の密度の差で求めます。偏微分には分けません。

**変えた理由**

偏微分に分けると、隣り合う質点の水蒸気圧の差を、1 次の近似で表すことになります。防湿層の両側や、断熱材の両側のように、隣どうしの温度や湿度の差が大きい所では、その近似の誤差が答えに残ります。Python 版は、熱と水分をニュートン法で一緒に解くので、分けなくても解けます。

**確認したいこと**

1. 偏微分に分けたのは、熱と水分を別々に、線形の式として解くためと考えてよいですか。ほかの理由（測定値との合わせ込みなど）がありましたか。

## 5 材料の熱容量に含める水と、液水が運ぶ顕熱

**Fortran 版**（241 行、883〜925 行）

```fortran
      GCP(I)=GCP(I)*GMA(I)
...
   D1=GCP(L5)*DX(IW,K)*AW(LW)/DTM
   D2=CPL*(DWLX(LW,I)*(WPU(LW,I-1)-WPU(LW,I))+DWLX(LW,I+1)*(WPU(LW,I+1)-WPU(LW,I))&
```

- 材料の熱容量は、乾燥した材料の容積比熱 × 厚さです。含まれる水の熱容量は入っていません。
- 熱の式に、液水の流れが運ぶ顕熱（CPL × 液水の流れ × 温度の差）の項があります。

**Python 版**（`modules/wall_geometry.py` の `MaterialNode.heat_capacity`、`modules/balance.py` の `heat_residual_is`）

- 材料の熱容量に、含まれる水の熱容量（水の比熱 × 水分量）を足しています。
- 液水の流れが運ぶ顕熱は入れていません。

**変えた理由**

参考にした講義資料の熱の収支の式と同じ項にしました。液水の流れが運ぶ顕熱は、液水の流れが小さい（今の材料では構造用合板の高湿域だけ）ので、ほかの項に比べて非常に小さいと考えています。含まれる水の熱容量は、木材などの湿った材料では乾燥した材料の熱容量の 1 割を超えることがあるので、入れました。

**確認したいこと**

1. 含まれる水の熱容量を入れなかったのは、意図したものですか。
2. 液水の流れが運ぶ顕熱の項を入れたのには、何か理由がありましたか。

## 6 水分化学ポテンシャルが 0 以上になったときの置き換え

**Fortran 版**（1236 行、1298 行）

```fortran
   IF(WPU(LW,I).GE.0.00)WPU(LW,I)=-1.3E-4
...
   IF(WPU(LW,I).GE.0.00)WPU(LW,I)=-1.3E-3      !-100.
```

水分化学ポテンシャルが 0 以上（相対湿度 100% 以上）になったら、通気層の空気の質点では $-1.3 \times 10^{-4}$ J/kg、材料の質点では $-1.3 \times 10^{-3}$ J/kg に置き換えて、計算を進めています。

**Python 版**（`modules/solver.py`）

ニュートン法の修正で水分化学ポテンシャルが 0 を超えないように上限を設け、それでも収支が合わない（結露した）ときは、計算を止めて、結露した質点を知らせます。結露した水（水膜・結露水）を扱うモデルは、これから作る予定です。

**変えた理由**

置き換えると、入りすぎた水分が消えて、水分が保存されなくなるためです。

**確認したいこと**

1. 置き換える値 $-1.3 \times 10^{-3}$ と $-1.3 \times 10^{-4}$ は、どのように決めた値ですか（コメントに残っている −100 との関係も含めて）。
2. 置き換えで消える水分は、水膜や結露水として別に数えていましたか。

## 7 室温の 1 年の変え方（SUBROUTINE ROOM）

**Fortran 版**（2092〜2101 行）

```fortran
      D1=2*3.1415*(KDAY-212)*24./8760
      TR=TRDT*COS(D1)+TRAV
```

室温は、通算日 KDAY ごとに余弦で決め、1 日の中では一定です（日ごとの段）。

**Python 版**（`modules/indoor_climate.py` の `CosineIndoor`）

室温は、時刻で滑らかに変わる余弦とし、いちばん暑い日（通算日 212）の 12 時に最も高くなるようにしています。円周率は `math.pi` を使っています。

**違いの大きさ**

振幅 4.5 K のとき、1 日の室温の変化は最大で約 0.08 K なので、日ごとの段との差は最大で約 0.04 K です。

**確認したいこと**

1. 日ごとの段にしたのは、計算を簡単にするためと考えてよいですか。

## 10 連立方程式の解き方（参考）

Fortran 版は、熱と水分を別々に、質点ごとの反復（緩和係数 OMG = 1.2）で解いています。Python 版は、熱と水分を一緒に、ニュートン法（帯のヤコビ行列）で解いています。物理の式は同じで、解き方だけが違うので、確認したいことはありません。

## 11 水膜（浸入した雨水）の扱い

**Fortran 版**（1140〜1197 行の水膜の計算、1223〜1231 行の通気層の空気の質点、1242 行の材料の質点）

```fortran
      D4=3.43E-08*(D3-VP)*0.3                                       !****濡れ面率0.3  水膜からの蒸発量
      IF(L5.GE.10.AND.L5.LE.12)THEN                                 !バックシーラー透水抵抗 2.4e+5 m2sPa/kg by　長村
         D1=1/(DX(IW,J)/3.73E-6+2.4E+5/DGDU)                        !飽和時の水分伝導率 3.73e-6 kg/ms(J/kg)　いぶし瓦 by 伊庭　D論
        ELSE
         D1=1/(DX(IW,J)/(3.73E-6*0.05)+2.4E+5/DGDU)                 !木製品を想定
      END IF
      RN(I,J)=(D1*D2+D4+SWJRAIN(I,J))*3600/NDVD+HRN(I,J)            !******水膜の水分量kg/m2
      WJRAIN(I,J)=-D1*D2*AW(I)
```

- 水膜は、浸入する場所として入力で指定した質点 J（通気層に面する材料の表面の質点）にあります。
- 材料への吸水の量は、水膜（水分化学ポテンシャル 0）と、**次の質点**（J − 1 または J + 1）の水分化学ポテンシャル D2 の差に、コンダクタンス D1 を掛けて求めています。
- 求めた吸水の量（WJRAIN）は、**表面の質点 J** の水分の式に足しています（1242 行の `D7=WJRAIN(LW,I)`）。
- 水膜からの蒸発（D4）は、湿気伝達率 3.43e-8 と濡れ面率 0.3 で求め、通気層の空気の質点の水分の式にも足しています（1223〜1231 行）。
- 水膜の水分量は、前のステップの値から前進差分で求め、0 以下になれば 0 にしています。

**Python 版**（`modules/wall_geometry.py` の `FilmNode`、計算方法の文書の根拠「境目にたまる水（水膜）のモデル」）

- 層と層の境目に、いつも水膜の質点を置きます。水膜の質点は、左右のつながり（境目のコンダクタンス 2 組）で、両側の質点と水蒸気・熱をやりとりします。
- 水膜があるかないかを、1 つの量（水膜の状態量）で表し、ほかの質点と一緒に後退差分で解きます。
- 雨水の浸入は、まだ作っていません。

**Fortran 版の扱いについて気づいた点**

1. 吸水の量を、次の質点との差で求めているのに、表面の質点に足しています。表面の質点から次の質点への流れは、別に通常の式でも計算されるので、二重に数えているおそれがあります。
2. 通気層の空気との水分のやりとりを、水膜からの蒸発（D4、濡れ面率 0.3）と、表面の質点からの流れ（通常の式）で別々に計算しています。水膜があるときに、両方を数えているおそれがあります。また、湿気伝達率を、水膜の計算（3.43e-8）と通常の式（入力の値）の 2 か所で指定していて、合っている保証がありません。
3. 水膜の水分量を前進差分で求めているので、そのステップの水膜の影響が、後退差分で解く水分化学ポテンシャルに入っていません。
4. 吸水の式の `DX(IW,J)` は、ほかの所では層の番号で引く配列ですが、ここでは質点の番号 J で引いています。別の層の分割幅を使っているように読めます。
5. バックシーラーの抵抗 2.4e5 は、コメントでは「透水抵抗」ですが、式では水分化学ポテンシャルの差に対するコンダクタンス（DGDU で割る形）として使っています。
6. 吸水の式は、材料の番号 10〜12 とそれ以外で分かれていますが、バックシーラーの抵抗（`2.4E+5/DGDU`）はどちらの分岐にも入っています。違うのは飽和時の水分伝導率（それ以外の材料では 0.05 倍）だけです。そのため、バックシーラーの抵抗が、どの材料の面にもいつもかかっています。
7. バックシーラーは、液水の吸水の式にだけ入っていて、水蒸気の経路には入っていません。入力ファイル（`mw1-d.dat`）のサイディングの通気層の側（内面）の湿気伝達率は 3.43e-8 で、通気層の表面の伝達と同じ値です。

**確認したいこと**

1. 吸水の量を表面の質点に足す扱い（気づいた点 1）と、蒸発を水膜と表面の質点で別々に計算する扱い（気づいた点 2）は、意図したものですか。
2. `DX(IW,J)` は、層の分割幅のつもりでしたか（気づいた点 4）。
3. バックシーラーの透水抵抗 2.4e5 m² s Pa/kg（長村）と、飽和時の水分伝導率 3.73e-6 kg/(m s (J/kg))（いぶし瓦、伊庭の博士論文）の出典を教えていただけないでしょうか。木製品で 0.05 倍にしている根拠もあれば教えてください。

## 12 雨水の浸入量

**Fortran 版**（496〜535 行、629〜639 行）


式にすると、浸入量 ＝ 浸水率（%）/ 100 × 1.5 × 0.2 × 風速 × cos（風向と壁の向きの角度）× 降水量 / 3600 で、ASHRAE Standard 160 の壁面の雨量の式（4-6）に浸水率を掛けた形です。風速は、レイリー分布で重みを付けて平均しています。

**Python 版**（`modules/rain.py`、計算方法の文書の評価方法「雨水の浸入」、根拠「境目にたまる水（水膜）のモデル」の 8 節）

- 風速は、気象データの風速を、測った高さから高さ 10 m の値に直して使います（ASHRAE Standard 160 の式の風速は、高さ 10 m の平均風速）。
- 雨水暴露係数と雨水付着係数は、ASHRAE Standard 160 の表から選んで、入力で与えます。
- 浸入する割合は、層と層の境目ごとに入力で与えます（ASHRAE Standard 160 のデフォルトは、防水層の外側の表面に 1%）。
- 風速の分布での平均はとりません（式が風速に比例するので、平均の風速を入れた値と同じになるため）。

**違い**

1. **風速の高さ**：Fortran 版は、風速を壁の高さ（階の中央 ＋ 基礎 0.7 m）の値に直したうえで、暴露係数 1.5 を掛けています。ASHRAE Standard 160 では、風速は高さ 10 m の値で、建物の高さの影響は暴露係数の表に入っているので、高さの影響を 2 か所で数えていることになります。
2. **暴露係数 1.5**：ASHRAE Standard 160 の表 4.6.1 では、1.5 は建物の高さが 20 m を超える場合の値です。高さ 10 m 未満なら、暴露の分類が「厳しい」でも 1.4、「普通」なら 1.0 です。
3. **付着係数**：Fortran 版には付着係数がありません（1.0 と同じ）。
4. **風速の分布の式の符号**：レイリー分布の式 f(v) の指数が `EXP(+3.14*0.25*(v/V)**2)` となっていて、正しくは `EXP(-…)` と考えられます。このままでは、速い風に大きな重みがかかり、平均の浸入量が、正しい値の約 2.8 倍になります（風速によらず同じ倍率）。
5. **浸入する場所**：例の入力では、通気層に面する 2 つの表面（サイディングの裏面と石膏ボードの表面）に 0.5% ずつ浸入させています。ASHRAE Standard 160 では、浸入した雨水は防水層の外側の表面にたまるものとしています。

1. 風速を壁の高さに直したうえで暴露係数 1.5 を掛けたのは、どのような考えによるものですか。
2. レイリー分布の式の指数の符号（違い 4）は、誤りと考えてよいですか。

- 質量減少率の合計が 0.6 を超えたら足しません。水分生成（I_HCOFF = 1）を選ぶと、質量減少率から求めた水を水分の収支に足します。

**Python 版**（`modules/decay.py`、計算方法の文書の評価方法「木材腐朽」、根拠「木材腐朽のモデル」）

- 木材腐朽を求める層は、層の入力（`wood_decay`）で指定します。
- 腐朽が始まるのは層の表面の質点（層の両端）だけとし、内部へは、同じ層の隣の質点の質量減少率が 0 より大きいときに広がるものとしました（齋藤ら 2008 の式 (11)・(12)）。
- 判定は、1 日の平均ではなく、計算の時間刻みごとの温度・相対湿度で行います。
- 温度・相対湿度が変わる場合の発芽は、その時刻の発芽までの時間で時間刻みを割った「進み具合」を足していき、1 に達したら発芽とします。続いた時間を、その時刻の発芽までの時間と比べる扱い（Fortran 版）では、発芽しにくい条件で過ごした時間も、発芽しやすい条件の時間と同じに数えられるためです。
- 腐朽で生まれる水は、水の密度を使って求め（齋藤ら 2008 の式 (16)）、1 つ前のステップの質量減少率の増えから、次のステップの水分の収支に必ず足します。
- 反応速度定数が負になる温度では 0 としました。
- 発芽までの時間の式の値 $-g/f$ が 0 以下のときは、Nofal・Kumaran（2011）の式 (11) の意味から、$f \le 0$ なら発芽しない、$f > 0$ で $g \ge 0$ ならすぐに発芽する、としました。下限 0.5 か月は設けていません（気づいた点 5）。
- 係数 W = −1 と上限 0.6 は、論文で決められないので、Fortran 版の値をそのまま使っています（確認したいことの 2・5）。

**気づいた点**

1. **「隣」の番号**：成長期の判定の `L_STAGE(K-1,I)`・`L_STAGE(K+1,I)` の K は、呼び出し側では壁の番号（LW）です。隣の質点ではなく、隣の壁の同じ番号の質点を見ています。また、壁の番号が 1 や最後のときは、配列の範囲の外を見ます。
2. **「隣」の条件**：齋藤ら（2008）の式 (12) では、材料の内部のセルで腐朽が進む条件は「隣のセルの質量減少率が 0 より大きい」ことで、菌糸は最初は表面のセルにだけいるとしています。Fortran 版は、どの質点でも発芽を判定し、隣が「発芽している」ことを条件にしています。
3. **値が残るか**：TIME_S と L_STAGE は、サブルーチンの中で宣言した配列で、SAVE がありません。コンパイラや最適化によっては、日をまたいで値が残らないおそれがあります。
4. **係数 W = −1（OSB）**：Nofal・Kumaran（2011）の式 (12)・(13) の係数は $WS$ で、樹種を表す $W$ と表面の状態（平滑か、のこ挽きか）を表す $S$ の積です。対象の樹種はヨーロッパアカマツとドイツトウヒで、$W$・$S$ の値は書かれておらず、OSB は対象に入っていません。
5. **発芽までの日数の下限と −0.59**：$t_i = -g/f$ が 0 以下のとき、−0.59 より大きければ 0（さらに下限 0.5 か月）、それより小さければ 100 か月としています。論文にはない扱いです。$t_i$ が 0 以下になるのは、$f \le 0$（相対湿度が低く、腐朽が始まらない。$t_i$ は −2.3 以下）と、$f > 0$・$g > 0$（高温・高湿で、すぐに始まる。$t_i$ は −0.70〜0）の 2 つの場合で、−0.59 はこれを分けるためと思われます。しかし、30 deg.C・100% では $t_i \approx -0.70$ で、すぐに始まるはずの条件が 100 か月（発芽しない）になります。Python 版では、$f$ の符号で分けました。
6. **反応速度定数が負になる温度**：$k_m(T)$ は、1.3〜2.7 deg.C で負になります（質量が増える）。齋藤ら（2008）の実験は 5〜40 deg.C で、3 次式の当てはめの範囲外と思われます。
7. **水分生成の密度**：齋藤ら（2008）の式 (16) は $W_L = h \rho_w \, dL/dt$ で、$\rho_w$ は水の密度です。Fortran 版は、材料の乾燥密度 GMA を掛けています。構造用合板（600 kg/m³）では、水分生成を約 0.6 倍に見積もることになります。
8. **上限 0.6**：質量減少率の合計を 0.6 で止めています。齋藤ら（2008）には、含水率 0.6 kg/kg までは質量減少率が直線的に増える、という記述がありますが、質量減少率の上限の根拠は見当たりませんでした。
